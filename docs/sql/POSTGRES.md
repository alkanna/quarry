# PostgreSQL support for Quarry (designs first, then phased implementation)

## Context

MySQL and MariaDB support is merged (#147). The SQL layer was meant to take a new engine as a new enum arm, but in practice it is bound to sqlx MySQL types: `Pool` has one variant destructured irrefutably in 32 places, about 130 signatures take `MySql*` types, `Dialect` is MySQL vs MariaDB with 36 `== Dialect::X` checks, the lexer and the read-only guard only know MySQL syntax, and the app assumes two name levels (database, table). The PostgreSQL card in the connection form exists but is disabled ("Coming later").

The user chose:
- **Scope:** v1 and v2, phased, v1 first. v1 is connect, browse, Content grid with edits, read-only Structure, Info, Relations and Triggers, Custom Query, autocomplete and the shell. v2 is structure editing, relations and trigger editing, import and export, dump, create and drop, and the Advanced tab. The MySQL v3 features (roles and grants, process list, variables) are out of scope and hidden for Postgres.
- **Schemas:** designs first in FigCraft, 2 or 3 variants for the sidebar and the connection form.
- **Servers:** PostgreSQL 13 and later, tested live on 13 and 18. 13 is past end of life (November 2025) and kept on purpose.

- [x] 5. Triggers (`feat: edit PostgreSQL triggers`). `Feature::TriggerEdit` is on for PostgreSQL. A trigger is two objects, so `ddl_pg_trig.rs` writes a change as `CREATE OR REPLACE FUNCTION` (only the body of the text `pg_get_functiondef` gave is replaced, so SECURITY DEFINER, SET clauses and every other attribute are carried through; a definition that cannot be taken apart exactly is refused), then `DROP TRIGGER IF EXISTS` and `CREATE TRIGGER` (13 has no OR REPLACE), then `ALTER TABLE .. ENABLE/DISABLE/ENABLE REPLICA/ENABLE ALWAYS TRIGGER` and `COMMENT ON TRIGGER`, in one transaction. A new trigger gets a new `CREATE FUNCTION "schema"."<table>_<trigger>_fn"() RETURNS trigger LANGUAGE plpgsql` (the name is editable, cut to 63 bytes, and a taken name is refused instead of replaced). The editor has timing (BEFORE, AFTER, INSTEAD OF), events (INSERT, UPDATE [OF columns], DELETE, TRUNCATE), ROW or STATEMENT, WHEN, the enabled switch and the plpgsql body; only the parts that changed are written (a body alone replaces the function, a switch alone is one ALTER TABLE). The body sits in a dollar quote whose tag (`$function$`, then `$functionx$` and so on) does not occur in it; WHEN goes through `check_cond_pg` (the expression scan) and every identifier is quoted; the server parses a plpgsql body at CREATE FUNCTION (`check_function_bodies` is set on for the transaction), so a syntax error rolls everything back. The table is locked at the weakest mode the statements need: ACCESS EXCLUSIVE only when the plan has a DROP TRIGGER, else SHARE ROW EXCLUSIVE, skipped for a view or foreign table and for a role without UPDATE, DELETE or TRUNCATE (then each statement takes its own under the 3 s lock_timeout). Under the lock the trigger (`pg_get_triggerdef`, enabled state, comment) and the function (`pg_get_functiondef`, owner, privileges, comment, and how many other triggers run it) are read again with the editor's own queries and compared (`Seen`), so another session's change stops the save; the state the change left is read before COMMIT and guards the undo. Undo replays the exact old `pg_get_functiondef` and `pg_get_triggerdef` with the enabled state and comments; a dropped trigger takes its function too only when it is a plpgsql function nobody else runs, owned by the connected role, with no privileges and no extension, and undo creates both (otherwise the function stays and the dialog says why). Warned in the preview: a function other triggers run, SECURITY DEFINER, another owner. - [x] 8. Create and drop database, schema and table (`create_pg.rs`, `sql_create_pg.rs`). `Feature::CreateDrop` is on for PostgreSQL. A database is made and dropped outside a transaction, one statement on a connection of its own taken from the pool of the connection's own database (never the one being dropped): `SET default_transaction_read_only = off`, `statement_timeout = 0` and `lock_timeout` on that connection only (not behind a pooler, where nothing can be set on a session), then `CREATE DATABASE "x" [TEMPLATE "t"]` (the template must be in the server's `datistemplate` list; the owner is the connected role) or `DROP DATABASE "x" [WITH (FORCE)]`. Before a drop `PgPools::close_database` removes and closes the database's live pool and every pool the LRU cap pushed out of the map (`Live::retired`, kept for exactly this, because an evicted pool keeps idle connections for the idle timeout and the server refuses the drop for them) within 5 s, the app closes the tabs and forgets the sidebar state of that database first, and a 55006 without FORCE closes the pools once more and retries once, because a read already in flight can make a pool again; the refusal that remains names the way out. FORCE is a checkbox in the typed confirm, off by default; the dialog shows the size, the number of sessions connected, whether it is a template, and says a drop has no undo. A connection cannot drop the database it opens on (Quarry keeps its maintenance pool there). Undo of a database create checks on a connection to it that no user relation, function, type or schema is in it, closes the pools, and drops without FORCE, so another session makes the server refuse; a table made in the instant between the check and the drop would go with it, as on MySQL. A schema is `CREATE SCHEMA` and `DROP SCHEMA [CASCADE]` in one transaction; the confirm lists what CASCADE would drop (a pg_depend walk that maps a view's rewrite rule to the view, so views of views and keys of other tables are found; first 20 and a count) and the drop stays disabled until CASCADE is ticked when that list is not empty. Undo of a schema create runs `DROP SCHEMA` without CASCADE in a transaction after comparing the schema's oid, so the server itself refuses a schema that holds anything, with no gap. The table builder (`PgNewTable`) is the structure editor's `ColDef` (type text, identity by default or always, default value or expression, comment, nullable), a primary key over the columns marked PK, a single-column UNIQUE per marked column and a table comment; `ddl_pg::col_body` is the one function that writes a column's clause for both ADD COLUMN and CREATE TABLE. One transaction: `lock_timeout`, `SET LOCAL search_path` to the schema (so a type of the schema resolves as it will when the structure editor reads it), a `to_regtype` check of every typed type, CREATE TABLE with server-named constraints, the comments, then the structure read back (`fingerprint`: every column, index, constraint and dependent) and the table's oid kept in the undo. Undo drops the table in one transaction after `LOCK TABLE .. ACCESS EXCLUSIVE` (skipped for a role without the privilege), comparing oid and fingerprint and checking it holds no row, and refuses with the reason otherwise (rows, changed structure, dropped and made again, gone, something depends on it, lock held). DROP TABLE and DROP VIEW list what depends on the table (the same walk, started from the normal dependencies only, since indexes, constraints and owned sequences go with a plain drop) with CASCADE as the opt-in, show the exact row count within 2 s or an estimate, and have no undo. Refused: postgres, template0 and template1 for create and drop (compared exactly: `Postgres` is another database), `pg_catalog`, `information_schema`, `pg_toast*` and `pg_temp*` for every schema and table statement, any new schema called `pg_...`, names over 63 bytes or with control characters, two columns that differ only in case. Sidebar: New schema, New table, Drop schema (the picked one) and Drop database in the database menu, Drop table or view in the table menu (Empty table is not offered), all enabled on a locked connection and all ask to unlock first, then go on with what was asked (this now holds for MySQL too). Behind PgBouncer a schema and a table are made and undone like anywhere; CREATE DATABASE works through it, and DROP DATABASE without FORCE is refused (the pooler holds a server connection on the database that Quarry cannot close) while WITH (FORCE) works, which the test checks. Tests: `pg_ddl_tests/create.rs` 13 live (two servers and the PgBouncer), `ui_tests/sql_create.rs` 4 flows on every SQL server and 2 on PostgreSQL, a pool unit test in `pg.rs`. Known limits: no encoding, locale or owner on a new database; no multi-column UNIQUE, CHECK, foreign key or index in the builder (Structure adds them next); the confirm's session count includes Quarry's own pooled sessions

**Layer 2 rules** (every step that runs user text: Content filter, Query, shell relay):
- Each user statement runs alone in `BEGIN READ ONLY` and is always rolled back, never committed, never sharing a transaction with another user statement.
- A pooled connection that ran user text is closed, not returned to the pool: `DISCARD ALL` releases advisory locks but not dblink connections opened by a wrapper. Pages with no user filter text keep using the pool.
- Pooler fallback mode: no session SETs; read-only, timeouts and formats are applied with `SET LOCAL` inside each transaction; the writer uses `BEGIN READ WRITE` plus `SET LOCAL`; statement pooling (where BEGIN fails) is refused with a clear message.
- Known limit: a user-defined or extension function that wraps a side effect is invisible to the lexer, and non-transactional effects (signals, WAL switches, slots, COPY TO PROGRAM through such a wrapper) are not undone by the rollback. A locked connection is therefore only as safe as the role's privileges; the README and the connection form should say so.

### Cloud SQL (v3)

The user opens Cloud SQL databases today with `cloud-sql-proxy --port 5432 --auto-iam-authn <project>:<region>:<instance>` and then connects to localhost. Quarry should do both: list the instances the current gcloud credentials can reach, and start and stop the proxy with the connection, the way it already opens an SSH tunnel.

- **Connection kind.** A Postgres connection gets a third way in next to Direct and SSH: "Cloud SQL", saved as the instance connection name (`project:region:instance`), IAM sign-in on or off, and public or private IP. No password is saved when IAM sign-in is on.
- **Discovery.** Through the gcloud CLI only, run as a child process and found like Bun with `find_exe`: `gcloud projects list --format=json`, then `gcloud sql instances list --project <p> --format=json` for PostgreSQL instances with region, state, IP kinds (public, private, PSC) and whether IAM sign-in is enabled (`cloudsql.iam_authentication`). The IAM user name is filled from `gcloud config get-value account` (a service account drops its `.gserviceaccount.com`). Decided 2026-11-11: no sign-in without the CLI; when gcloud is missing the form says so and links to its install page.
- **The proxy.** Run the official `cloud-sql-proxy` binary as a child process, with `--auto-iam-authn` when IAM is on, and `--private-ip` or `--psc` per the saved choice (both in the first version, decided 2026-11-11). Stop it when the connection closes, a connect is cancelled, or Quarry quits or restarts into an update. Its output goes to the status bar list on failure. Nothing secret is on its command line (never `--token`, which `ps` would show): it reads the Google credentials itself, which keeps the rule against passwords on command lines. `CSQL_PROXY_*` variables are removed from its environment, since they change its socket, credentials file and API endpoint.
- **Where it listens (decided 2026-11-12, security review).** A localhost port can be taken by any local user between Quarry picking it and the proxy binding it, and a plain connect check then trusts the squatter, which with IAM off and sslmode off receives the password; an open IAM port also lends the IAM identity to every local user. So on macOS and Linux the proxy gets an exact unix socket, `<instance>?unix-socket-path=<dir>/.s.PGSQL.5432` (the value is query-encoded, the proxy decodes it), in a fresh folder from `update::fresh_temp_dir` set to 0700 before the proxy starts and removed with the connection. sqlx connects with `PgConnectOptions::socket(dir)` and port 5432. The path must fit sun_path (103 bytes on macOS, 107 on Linux); a longer temp folder is refused with a message naming TMPDIR. It is ready when the socket accepts a connection while the child is alive. On Windows sqlx has no unix socket, so it stays a TCP port, and the proxy counts as ready only after it printed "ready for new connections" on stdout while alive, then accepts a TCP connect. Known limit on Windows: the pick-then-bind race and any local user reaching the open port remain.
- **Credentials (decided 2026-11-12).** The proxy refuses `--gcloud-auth` together with `--auto-iam-authn` ("cannot use --auto-iam-authn with --gcloud-auth. Instead use Application Default Credentials"). So IAM sign-in always uses Application Default Credentials, and the gcloud account is used (`--gcloud-auth`) only for a password sign-in, when gcloud has an account; otherwise ADC. Before an IAM proxy starts, Quarry checks that ADC exist the way Google's auth library looks: the file `GOOGLE_APPLICATION_CREDENTIALS` names, else `application_default_credentials.json` in `$CLOUDSDK_CONFIG`, `%APPDATA%\gcloud` on Windows or `~/.config/gcloud`. Missing, the connection fails with a card asking for `gcloud auth application-default login`, and the browser shows the same card when Use is clicked on an IAM instance. The form still fills the IAM user from the gcloud account, and says the proxy signs in with ADC, which must be that same account; an IAM refusal names ADC as the likely mismatch. Known limit: ADC served only by a Google Cloud VM's metadata server is not seen, so IAM from such a VM needs the file.
- **gcloud calls** are stopped after 30 s (5 min for `components install`), with their process group on macOS and Linux and a job object on Windows, so a hung gcloud never keeps a connection connecting or the browser loading. Refresh never runs more than 6 instance lists at once: lists of a replaced load count until they end. gcloud runs with `PYTHONUTF8=1`, so its Windows output is UTF-8. Settings looks for gcloud once each time it opens, off the UI thread, and the demo shows a fixed path.
- **Finding or getting the proxy.** Look on PATH (absolute entries only), then in Quarry's tools folder (only verified downloads land there), then in the gcloud SDK's own `bin` (`gcloud info --format="value(installation.sdk_root)"`), where `gcloud components install cloud-sql-proxy` puts it, then Homebrew's folders on macOS only (on Windows `C:\opt\homebrew\bin` is a folder any user may create). Bun and the MongoDB tools are found by the same rule. When it is missing, offer two buttons: install the gcloud component (only when gcloud manages its own components; package-manager installs refuse it), or download Google's release for this platform into Quarry's data folder, verified against the published SHA-256 before it is ever run, the same rule as the self-updater. Decided 2026-11-11: the download is offered.
- **Later, if the binary is a burden:** connect natively. Google publishes connector libraries for Go, Java and Python but not Rust; the protocol (Admin API `connectSettings` and `generateEphemeralCert`, then TLS to the instance with the ephemeral certificate, and the IAM token as the password) could be done in Rust, but only once the proxy version has shown what users need.
- **Read-only.** Unchanged: the proxy is only the way in; the session guard, the per-statement read-only transaction and the lexer apply as for any Postgres connection. A role reached through IAM is still only as safe as its grants (the locked note in the form says so).
- **Tests.** Discovery parsing from recorded `gcloud ... --format=json` output; proxy start, ready, stop and failure with a stub binary on PATH; one manual check against a real instance before ticking.

## Implementation

### Core decisions

1. **The engine boundary is an enum, not generics.** New `src/db/sql/exec.rs`:
   - `enum Conn { My(MySqlConnection), Pg(PgConnection) }`, `enum SqlRow { My(MySqlRow), Pg(PgRow) }` (zero-copy `raw(i)`, `text(name)`, `cols() -> Vec<ColInfo{name, ty}>`), `enum Opts`.
   - Helpers: `fetch_text`, `execute`, `exec_bound(sql, &[Param])`, `fetch_bound`, `close`, `Db::detached`.
   - Generics over `sqlx::Database` were ruled out: higher-ranked bounds in every signature, raw bytes mean different things in text and binary rows, and USE vs a pool per database, KILL vs `pg_cancel_backend` and `last_insert_id` vs RETURNING would still need a match.
   - MySQL-only modules (ddl, create, dump, import, users, server, advanced) keep their sqlx types through `Db::my_pool()` and `Conn::my()`, which return "not available for PostgreSQL yet" until their v2 step.
2. **Connection model.** A Postgres connection is bound to one database; there is no `USE`.
   - `Pool::Pg(Arc<PgPools>)` holds the options without a database and `Mutex<HashMap<db, PgPool>>`, created lazily with `connect_lazy_with`.
   - Caps: 3 connections per database, at most 4 live pools (least recently used is evicted and closed in a spawned task), 5 minutes idle.
   - The default database is `Addr.database`, or `postgres` when empty. Databases come from `pg_database` where `datallowconn AND NOT datistemplate AND has_database_privilege(.., 'CONNECT')`.
   - Servers below `server_version_num` 130000 are refused with a clear message. TLS state comes from `pg_stat_ssl`.
3. **Namespace with least churn.**
   - `Sel` gains `schema: String`, empty for Mongo and MySQL (Sel derives Default).
   - `Conn.dbs` keeps its shape. On Postgres its inner list holds schemas, and a new `Conn.tables: HashMap<(db, schema), Vec<String>>` holds tables. `Msg::SqlTables` gains `schema`.
   - Worker `schema` parameters mean "the namespace inside the bound database": the database on MySQL, the schema on Postgres. `qualified()` stays two-part (`"schema"."table"`); the database only picks the pool.
   - New `App::sql_target(&Sel) -> Option<(Db, String)>` replaces `sql_db_for`.
   - `sql_schema` stays keyed `(conn, db)`. One load covers every non-system schema, and `SchemaTable` gains `ns`.
4. **Values.**
   - Data rows (Content, Query, relay) go through `raw_sql`, the text protocol, as on MySQL.
   - Bound metadata queries return binary rows, so their columns are cast `::text`.
   - Session start sets `bytea_output=hex`, `DateStyle=ISO`, `IntervalStyle=postgres`, `application_name=Quarry`.
   - New `value::Kind`s: Bool (`t`/`f`), Uuid, Array, Interval, Inet, Range, and user enums, mapped from `pg_type.typcategory` through domains (`typbasetype`). bytea decodes `\x` hex at the edge. Arrays, ranges, money and composites show as text in v1.
5. **Writes.**
   - `$n` placeholders written as `CAST($n AS <format_type>)`, because Postgres refuses a text value for an int column.
   - No `LIMIT 1` on UPDATE or DELETE (`write.rs` adds it today), `DEFAULT VALUES` for an empty insert, `RETURNING <pk>::text` for new keys.
   - `=` on key columns so indexes are used; `IS NOT DISTINCT FROM` only in old-value checks.
6. **Read-only guard, three layers** (opus security review):
   - **Session:** startup option `default_transaction_read_only=on`, read back with `SHOW` together with `standard_conforming_strings=on`; the connection is refused on a mismatch.
   - **Transaction:** every statement that carries user text on a locked connection (Content page and count, Query, shell relay) runs in `BEGIN READ ONLY` and is rolled back. The rollback undoes `set_config(.., false)`, SET, NOTIFY and transaction advisory locks. Without it, `SELECT set_config('default_transaction_read_only','off',false)` would unlock the pooled session.
   - **Lexer:** allows SELECT, WITH, VALUES, TABLE, SHOW, and EXPLAIN without ANALYZE (including the `(ANALYZE ..)` form; the inner statement is checked). Refuses SET, RESET, BEGIN, START, COMMIT, COPY, DO, CALL, SELECT INTO, LISTEN, NOTIFY, PREPARE, EXECUTE, DECLARE, LOCK, MERGE, psql `\` commands, and data-modifying CTEs at any depth. Refuses these functions in any spelling (plain, schema-qualified, quoted): set_config, pg_terminate_backend, pg_cancel_backend, pg_reload_conf, pg_rotate_logfile, pg_switch_wal, pg_create_restore_point, pg_promote, pg_advisory* and pg_try_advisory*, dblink*, lo_*, pg_file_*, pg_logical_emit_message, *replication_slot*, pg_replication_origin_*, pg_stat_reset*, pg_stat_statements_reset, pg_backup_*, pg_start_backup, pg_stop_backup, pg_wal_replay_*, pg_log_backend_memory_contexts, pg_import_system_collations, pg_notify, nextval, setval.
   - **Known limit:** a SECURITY DEFINER function wrapping one of these is invisible to the lexer.
   - **Query log:** redaction learns `PASSWORD '...'` in CREATE and ALTER ROLE or USER.
   - **Writer:** a detached connection with `SET SESSION CHARACTERISTICS AS TRANSACTION READ WRITE`, `statement_timeout=0`, and a `lock_timeout` for DDL.
7. **Cancel and timeout.** `prepare` stores `pg_backend_pid()` and `backend_start`. Stop runs `SELECT pg_cancel_backend(pid) FROM pg_stat_activity WHERE pid=$1 AND backend_start=$2` on a side connection, so a reused pid is never hit. The timeout is `statement_timeout`.
8. **TLS.** `SslMode` maps to `PgSslMode` (Disable, Prefer, Require, VerifyCa, VerifyFull). URIs use the libpq spellings `sslmode` and `sslrootcert`; `allow` reads as Preferred. Through SSH, VerifyFull drops to VerifyCa as on MySQL. The default port follows the scheme (5432).

DDL is transactional, so the plan and its undo each run in one transaction, with the `expect` snapshot checked inside it after `LOCK TABLE` and a `lock_timeout`.
4. **Relations and FKs** through the same plan path; sql_rel.rs reused.
5. **Triggers** as a function and trigger pair in one transaction, DROP then CREATE (13 has no CREATE OR REPLACE TRIGGER); undo replays `pg_get_functiondef` and `pg_get_triggerdef`; a warning when the function is shared by other triggers.
6. **CSV import:** batches of `min(500, 65535 / cols)` rows, `ON CONFLICT (pk) DO NOTHING` or `DO UPDATE SET c = EXCLUDED.c`, undo keys from RETURNING, one transaction. Export: `stream_conn` takes `Conn`.

### Watch out

- sqlx-postgres sets its own startup parameters (TimeZone, DateStyle, extra_float_digits). Check them before deciding how timestamptz text is shown.
- PgBouncer in transaction mode rejects startup `options` and cached prepared statements: fall back to SET plus readback, and `persistent(false)` for user text.
- DDL takes ACCESS EXCLUSIVE, which queues readers behind it: always a `lock_timeout` on the writer.
- An error aborts the transaction until ROLLBACK: rely on sqlx `Transaction` drop.
- Unquoted identifiers fold to lowercase: rules and filters must quote names.
- Several pools per connection count against the server's `max_connections`: keep the caps.
- Live tests share servers and run in parallel: unique tables per test in one `quarry_test` database (tolerate 42P04 on create), never `ALTER SYSTEM` or `ALTER DATABASE SET`.
